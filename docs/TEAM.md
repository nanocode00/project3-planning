# 3인 팀 운영 — 분담 제안

**3명은 사용자 확인을 반영한 계획 전제**입니다. 조 번호·이름·주제·실명 담당은 미정입니다. 공식 역할은 검색/데이터, 에이전트, 서비스/운영, 평가/문서의 4종이므로 3인은 겸임하고 전원 보조 축을 하나 갖습니다(PDF p.15).

운영 방법은 [H21 WBS·정본·커밋/PR](COURSE_GUIDE.md#h21), T01~T09의 수업 근거는 [조건별 대응표](COURSE_COVERAGE.md)를 봅니다.

개발·문서·Git/PR·검증·CI 사용량 절감 규칙은 [팀 운영 정책 통합 초안](TEAM_POLICY.md)에서 관리합니다. 이전 프로젝트 공통 정책과 사용자 CI 추가안을 반영했으며, 팀 합의와 공식 저장소의 실제 설정은 별도로 확인합니다.

| 자리표시자 | 주담당 제안 | 겸임 제안 | 보조 담당 제안 | 주로 연결되는 기준 |
|---|---|---|---|---|
| A | 검색·데이터(②) | 평가셋·검색평가 | 에이전트③ 검토 | G3·G5, E2 |
| B | 에이전트(③) | 신뢰성 평가·실패 분석 | 서비스④ 검토 | G4·M, E3 |
| C | 서비스·운영(④) | Spec·시장근거①·제출 총괄⑤ | 검색② 검토 | G1·G2·G6·G7, E1·E4·E5 |

C에게 문서 작성 전체를 몰지 않습니다. A는 코퍼스/평가 증거, B는 그래프/실패 증거, C는 운영 증거를 직접 작성하고 C는 제출 목록을 취합하는 **팀 제안**입니다. 포트폴리오·발표·설계 설명은 전원이 맡습니다. 실제 역량·희망에 따라 교체합니다.

## 공식 운영 체크리스트 (PDF p.13~15)

- [ ] **T01** 전원 주담당·보조담당 확정, 다음 할 일 칸이 있는 백로그 운영.
- [ ] **T02** 매 작업일 아침 **15분** 스탠드업. 담당·차단 이슈·다음 작업을 날짜별 기록.
- [ ] **T03** 매주 **20분** 전원 점검. 날짜 제안: 11/6·11/13, D0는 역할 합의(점검 요일은 공식 지정 아님).
- [ ] **T04** 작은 PR, 최신 main 충돌 확인, 코드 변경 시 SPEC도 같은 PR로 갱신.
- [ ] **T05** 첫 기능 구현 전 Spec·평가셋 초안 커밋. 11/3 v1·11/6 v2의 공식 동결 일정과 구분.
- [ ] **T06** 질문 작성자는 정답 청크를 보지 않고 작성, 다른 팀원이 정답 근거 찾기·판정.
- [ ] **T07** 인터페이스 계약에 함수·입출력·예외뿐 아니라 파일·환경변수·코퍼스 버전·상태 소유권 기록(Checkpoint).
- [ ] **T08** 외부 검토1명, 동일 질문5개 대체재 비교, 전원 발표·개인별 포트폴리오 준비.
- [ ] **T09** AI 도구·위임·막힌 점·직접 고친 곳 기록, 아키텍처 이유는 본인 언어로 설명.
