## 5축 100점

축별 총점만 공개되어 있습니다. 아래 체크 개수로 점수를 비례 배분하거나 세부 배점을 추정하지 않습니다.

### ① 문제와 시장 근거 — 15점

- [ ] **E1-1** 목표 직무·산업의 **채용 공고 50건**을 근거로 요구 역량과 주제 선정 이유 정리. RAG 코퍼스와 별도 집계.
- [ ] **E1-2** 목표 사용자·반복 문서 업무·문제 정의·페르소나·고객 여정 맵 제시. 인원·페이지 수의 추가 공식 하한은 없음.
- [ ] **E1-3** 같은 질문 **5개**를 범용 챗봇과 나란히 비교. 답변·근거·차이·한계 제시.
- [ ] **E1-4** 사용자와 지불 주체, 실재성 근거를 제시. 아직 가설이면 가설로 명시.
- [ ] **E1-5** 외부 시선 **1명**의 검토와 반영 기록(팀 운영·D10 요구).

### ② RAG 품질 — 25점

- [ ] **E2-1** 코퍼스 선정 이유, 문서 ≥50·고유 청크 ≥10,000 집계, 파싱 원문 대조 ≥3건. [G3](GATES.md) 연결.
- [ ] **E2-2** 청킹·임베딩 선택에서 **둘 이상 비교한 근거** 제시. 각각 2개 이상 대안을 비교하는 구성을 팀 제안으로 권장; 원문은 조합별 최소 실험 수를 명시하지 않음.
- [ ] **E2-3** BM25+벡터 하이브리드·리랭킹·메타데이터 필터 구현, 변경 전후 측정. 한 번에 하나만 변경.
- [ ] **E2-4** 평가셋 v1/v2·사람 판정·4종 비관련·동결·예외 관리. [G5](GATES.md) 연결.
- [ ] **E2-5** 실패 문항을 유형별로 묶고 시도·원인·변경 후 결과 제시. 실패 유형 수의 공식 하한 없음.
- [ ] **E2-6** 후처리 필터가 검색 결과를 0~2개로 줄여 거절 성능을 부풀리지 않는지 확인. 사용하면 필터 효과 별도 보고(Checkpoint 추가 주의사항).

### ③ 에이전트 설계와 신뢰성 — 25점

- [ ] **E3-1** 그래프여야 하는 이유·노드 책임·역할별 컨텍스트 경계 제시. Supervisor+서브에이전트 ≥2. [G4](GATES.md) 연결.
- [ ] **E3-2** 근거 부족 → 질의 재작성 → 재검색 경로와 종료 조건. 재시도 상한 수치는 팀이 사전 결정(공식 2회로 고정된 요건은 없음).
- [ ] **E3-3** 단일/멀티를 같은 v2로 비교. 개선 없음·악화도 원인과 함께 기록.
- [ ] **E3-4** 사람 승인 ≥1곳, 체크포인트·재시작 재개, 사용자별 thread/Store·DB 시멘틱 메모리 증거.
- [ ] **E3-5** 답변 인용이 실제 검색된 문서에 존재하는지 **코드로 검증**. 근거 부족 시 거절.
- [ ] **E3-6** 코퍼스에 심은 간접 인젝션·출처 유출 시험을 **총 ≥3건**, 출처 유출 유형 포함. 원문은 각 유형 3건씩을 요구하지 않음.
- [ ] **E3-7** 신뢰 경계 **1장**: 믿지 않는 입력·시험 전후·남은 위험. 통과를 전체 안전 보장으로 쓰지 않음.
- [ ] **E3-8** G4/G5 핵심 코드 변이 검증 ≥3건과 실제 실패·원복 증거. [M 항목](GATES.md) 연결.

### ④ 배포와 운영 — 20점

- [ ] **E4-1** 깨끗한 clone에서 키 없는 데모 포함 compose ≤10분, 로그인 계정 2개. [G1/G2](GATES.md) 연결.
- [ ] **E4-2** 배포 URL, `/health`, 질의 API, 오류 응답 규약. 플랫폼 예외는 G1 기준.
- [ ] **E4-3** 현재 코드 기준 검색·리랭킹·생성·승인 대기별 시간과 비용 실측. 코드 변경 시 재측정.
- [ ] **E4-4** Langfuse 트레이스·평가 연결, 스크린샷 ≥3장(상세 ≥1장). [G6](GATES.md) 연결.
- [ ] **E4-5** 평가 회귀·동결 해시 확인을 CI에 연결. 조 저장소에서 Actions가 실제 시작·완료되는지 확인. 결제 제한은 코드 통과 증거가 아님.
- [ ] **E4-6** 원시 결과 + 평가 **한 줄 재현 명령**. 평가자가 샘플 문항을 다시 실행 가능.
- [ ] **E4-7** 조당 **$30 OpenRouter 한도** 내 사용 기록. 100건 임베딩 속도·비용으로 전체 처리 일정 추정. 안내의 과거 측정값을 우리 실측으로 쓰지 않음.

### ⑤ 증거 패키지와 발표 — 15점

- [ ] **E5-1** 동작 배포 주소·개선 전후 평가 리포트·운영 트레이스·실패 사례 분석 네 가지 증거 연결.
- [ ] **E5-2** 영상 ≤180초, 정상1+실패1, 화면별 해설. 발표자료는 문제 → 구조 → 지표 → 한계.
- [ ] **E5-3** **3명 모두** 발표 파트 담당. 각자 포트폴리오 1장(**총3장**, Checkpoint 기준), AI 도구 사용 기록 1장.
- [ ] **E5-4** 현장 라이브 입력 **3개(정상·경계·방어)**에 대비하고 배포·API 잔여 한도 점검. 응답 재생은 이 라이브 증거를 대신하지 않음.
- [ ] **E5-5** [발표 질문 11개](CHECKPOINT.md)의 설명을 전원이 준비. AI 작성 코드도 설계 이유를 직접 설명.

## 실험 순서 — 팀 제안, 공식 횟수의 해석과 구분

G5 원문은 “개선 전후를 두 번 이상”입니다. 누락을 줄이기 위해 **베이스라인 → 개선1 → 개선2**를 비교 가능한 상태로 남깁니다. 이는 모든 요인의 조합을 전수 실험하라는 뜻이 아닙니다.

| 시점 | 평가셋 | 측정 내용 | 남길 것 |
|---|---|---|---|
| 11/3 D2 | v1 30건 | 검색 베이스라인 | Recall@k·MRR, 원시 결과, 코드/코퍼스 버전 |
| 11/4 D3 | 같은 v1 | 하이브리드·리랭킹 등 각 변경 비교 | 변경 전 사전 등록, 단일 요인, 문항별 차이 |
| 11/5 D4 | v1 | 단일 그래프 기준 | 단일 원시 결과·트레이스 |
| 11/6 D5 | 동결 v2 ≥50건 | 단일을 v2로 다시 측정, 멀티와 비교 | 동일 v2·판정 기준, 두 상태 SHA |
| 11/12 D9 | 같은 v2 | 검색 실패 분석 후 개선2 | 개선 전/후, 제외 ID·사유(해당 시) |
| 11/16 동결 전 | 같은 v2 | 현재 제출 코드의 최종 재측정 | 최종 SHA·환경·비용·지연·재현 명령 |

측정 조건: 실행일, 코드 SHA, 평가셋 SHA-256, 코퍼스 버전·정답 기준일, 모델/프롬프트/파라미터, 캐시 여부, 제외 ID, 실행 환경을 남깁니다. v1 점수와 v2 점수를 직접 개선폭으로 비교하지 않습니다. 바뀐 문항이 1~4건이면 큰 개선으로 단정하지 않습니다.

## 지표 5개 — 공식 분류 / 분모는 팀 정의

공식은 아래 5종 분리 보고를 요구하지만 분모와 판정 계산식을 지정하지 않았습니다. 아래는 **팀 제안**이며 구현 전에 확정합니다. 문항별 판정 원시값과 `건수/분모`를 함께 보고하고 필요하면 제외 전후 건수도 남깁니다.

| 공식 지표 | 팀 제안 계산 | 방향 |
|---|---|---|
| 정답 근거 인용률 | 관련 질문 중 유효한 정답 근거를 인용한 수 / 유효 관련 질문 수 | 높을수록 좋음 |
| 오답 근거 | 관련 질문 중 틀리거나 불일치하는 근거를 제시한 수 / 유효 관련 질문 수 | 낮을수록 좋음 |
| 과잉 거절 | 관련 질문 중 거절한 수 / 유효 관련 질문 수 | 낮을수록 좋음 |
| 올바른 거절 | 비관련 질문 중 올바르게 거절한 수 / 유효 비관련 질문 수 | 높을수록 좋음 |
| 환각 위험 | 비관련 질문 중 근거 없이 답한 수 / 유효 비관련 질문 수 | 낮을수록 좋음 |

오답 근거·과잉 거절 등의 중복 허용 여부, 부분 답변·인용 누락·오류 응답 판정은 팀 판정 규칙으로 먼저 정의합니다. 분모 0은 `N/A`로 표기합니다. 검색 Recall@k·MRR은 별도 보고하고 k·복수 정답 처리 방식을 고정합니다.

공식 정확도/Recall/응답 시간 합격선은 없습니다. 서비스 SLO·루프 상한·예산 분배는 `미정`이며 결정 후 SPEC에 기록합니다. 가이드의 0.60~0.75는 사전 기대의 예시입니다.
