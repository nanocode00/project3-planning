## G1 — 배포·접근

- [ ] **G1-1** Cloud Run 배포 주소를 README에 기록. 2차에서 다른 플랫폼을 썼으면 그 플랫폼을 이어 사용 가능.
- [ ] **G1-2** 평가용 실서비스 테스트 계정 **2개**로 로그인해 핵심 시나리오를 끝까지 확인. 원문은 영상 대안도 허용하지만 로그인 구현 자체는 필수.
- [ ] **G1-3** 계정은 강사에게 **별도 DM 비공개 제출**, 저장소에는 비밀번호를 적지 않음. 배포를 발표일까지 유지.

증거: 배포 URL, `/health` 결과, 두 사용자 시나리오 결과, 비밀값을 제외한 제출 확인 기록. 관련: [제출물](DELIVERABLES.md).

## G2 — 한 줄 기동

- [ ] **G2-1** 새 clone/깨끗한 환경에서 `docker compose up` 한 줄로 **10분 이내** 준비 완료. 시작·완료 시각과 환경 기록.
- [ ] **G2-2** API 키·Supabase 계정 없이 데모 실행. **로컬 pgvector 컨테이너 + 스냅샷 + 기록된 응답 재생**을 준비(PDF p.19).
- [ ] **G2-3** 데모 전용 계정 **2개** 시드로 로그인 가능. 실서비스 평가 계정과 다른 값 사용.
- [ ] **G2-4** README에 실행·데모 방법과 사전 준비 명시. 로컬 모델을 쓰면 다운로드 없이 `HF_HUB_OFFLINE=1` 실행 확인.

증거: 깨끗한 환경 기동 로그·소요 초, compose 설정, 데모 양 사용자 시나리오. 재생 결과를 라이브 성능으로 보고하지 않음.

## G3 — 코퍼스

- [ ] **G3-1** 서로 다른 문서 **≥50건**. 채용 공고 50건과 별개이고 채용 공고는 청크 수에서 제외.
- [ ] **G3-2** 본문 SHA-256이 다른 청크 **≥10,000개**. 복제·약간의 변형으로 수를 늘리지 않음. **20,000개는 권장**, 필수 하한 아님.
- [ ] **G3-3** PDF·표·스캔 중 문서 파싱 **≥1종**. 원문과 결과 대조 **≥3건** 기록(축②의 별도 증거도 충족).
- [ ] **G3-4** manifest로 문서 수·중복 제거 청크 수를 재계산 가능. 출처·수집일·문서별 청크 수·본문 해시·원문 길이·보존 길이·잘림 여부 기록.

증거: `data/manifest.jsonl` 등 실제 manifest, 집계 명령·원시 집계, 파싱 대조 기록, 재배포 조건.

## G4 — 상태·멀티에이전트·사용자 기억

- [ ] **G4-1** LangGraph 상태 그래프, 조건부 라우팅, **Supervisor 1 + 서브에이전트 ≥2**. 각 책임·컨텍스트 경계 설명.
- [ ] **G4-2** 체크포인트와 사람 승인 `interrupt` **≥1곳**. 승인 전 멈춤·승인 후 재개, 재시작 후에도 재개 확인. 보고서 저장 전 승인 같은 행동 가능.
- [ ] **G4-3** 로그인 구현. 인증된 사용자 ID를 기준으로 `thread` 소유권·Store namespace를 나누고 계정 A/B의 대화·기억이 섞이지 않음.
- [ ] **G4-4** **DB 기반 Store의 시멘틱 메모리**: 기억 선택 기준, State/Store 경계, 검색·활용, 잘못된 기억 수정 절차 설명·실행.
- [ ] **G4-5** 단일 그래프를 먼저 측정하고 멀티와 **같은 v2**로 비교. 개선이 없어도 분석 기록. 최종 단일 구조로 회귀하면 G4 감점 대상.

증거: 그래프 그림·코드, 승인·재시작 로그, 사용자 격리 결과, Store 검색·수정 결과, 비교 리포트. 단순 테스트 PASS만으로 완료 아님(아래 M 항목).

## G5 — 동결 평가·재측정

- [ ] **G5-1** 11/3 v1 **30건=관련15+비관련15**, 사람 판정·근거 위치·SHA-256 동결.
- [ ] **G5-2** 11/6 중간 점검 전에 v2 **≥50건**, 관련·비관련 각각 절반. v1 유지 후 관련10+비관련10 이상 추가, v2 해시 동결.
- [ ] **G5-3** 비관련 질문 **4종**(도메인 밖·없는 대상·없는 항목·다른 기간)을 혼합하고 실제 코퍼스에 답이 없는지 확인. 질문 작성자와 정답 근거 판정자 분리.
- [ ] **G5-4** 개선 전후를 **두 번 이상** 재측정, 조건별 원시 결과·변경 문항 ID·재현 명령 보관. [실험 계획](EVALUATION.md)의 팀 제안은 베이스라인+개선1+개선2 세 상태.
- [ ] **G5-5** 단일/멀티 및 v2 이후 비교에 동일 v2·판정 기준 사용. 사전 등록된 기대를 사후 수정하지 않음.
- [ ] **G5-6** 동결 후 코퍼스 변경으로 정답이 바뀌면 원본 평가셋을 고치지 않고 `evals/exclusions.json`에 ID·사유 기록. 제외 후 50건 미만이어도 원문은 허용.
- [ ] **G5-7** 인용·오답 근거·과잉 거절·올바른 거절·환각 위험 **5지표 분리**, 건수와 분모도 보고. 1~4문항 차이는 변경 문항과 원인 분석 제시.

증거: v1/v2·해시, 사람 판정표, 제외 파일(해당 시), 실험 사전 기록, 원시 결과, `EVAL_REPORT.md`.

## G6 — 관측

- [ ] **G6-1** Langfuse 또는 동급에 실제 호출 트레이스가 남고 해당 평가 점수와 연결.
- [ ] **G6-2** 대시보드 스크린샷 **≥3장**, 그중 트레이스 상세 **≥1장**, 비용·응답 시간 포함.
- [ ] **G6-3** 현재 코드 SHA와 실행 조건을 기록하고 검색·리랭킹·생성·승인 대기 단계별 비용·시간을 구분.

증거: 비밀값을 가린 화면, trace ID·평가 ID 매핑, 계측 원시 결과. 소스에 화면 캡처 파일명 대신 실제 경로를 연결.

## G7 — 문서·비밀값·영상

- [ ] **G7-1** README: 누구의 어떤 문제인지 한 줄, 지표표, 실행법, 데모 모드.
- [ ] **G7-2** `.env.example` 제공, 비밀값 커밋 없음(제출 대상 이력 포함 확인). 계정 비밀번호는 비공개 제출.
- [ ] **G7-3** 시연 영상 **≤180초**, 정상 **≥1경로** + 실패 **≥1경로**, 화면마다 한 문장 해설.

증거: README·설정 예시·검토 기록·영상 링크와 재생 길이.

## 감점 기록

미확인은 미충족 확정이 아닙니다. 현재 점수를 계산하지 않습니다. 평가 시 G별 판정 후 감점 합계를 최대 50으로 제한하고, 하나라도 미충족이면 가산점을 적용하지 않습니다. 세부 항목별로 게이트 감점을 중복 계산하지 않습니다.
